# 收银确认说明

> 状态：**已锁死**（2026-11-21 当日锁死）。改动本说明须先走破锁评审。
> 适用范围：`/api/bookings/confirm` 确认写口及其档锁。

## 钉死口径：甲路径（持档锁 + 同事务双写）

并发确认必须互斥落库。正确性口径只走**甲路径**，乙路径（确认草稿原子晋升）不采用，两边不得混用。

甲路径定义：

1. **先持档锁**：确认写口必须先抢到 `slot:<档期码>` 档锁。抢锁 INSERT 零等待，撞锁即败；抢到后锁行立即落库、对外可见，排他持有至写口结束。未持锁不得进入写口。
2. **同事务双写**：持锁后在**同一事务**内插正式行（bookings）并加占用数（slots.booked），同步翻占位态（holds.status）与写审计。
3. **失败同滚**：事务内任一步失败，插入与加计**同事务同滚**，正式零增、占用零增，随后释放档锁。

## 争用规则

- 两边同时确认同一占位（含同人连点）须抢档锁，**后到只留争用痕**（contention_log 一行），不得写任何业务行。
- 争用痕必须当场落库，不随后续回滚。
- 锁不认同人：同一账号第二请求与异账号同等待遇，一律争用。

## 禁止项

- **禁止只挡双击**：不得以前端防抖、按钮置灰、请求去重代替落库互斥。
- **禁止乙路径混入**：不得引入确认草稿/晋升机制。
- **偏航处理**：确认写口若未持档锁（偏了），记 `收银确认偏航` 审计并**拒写**。

## 五处同态验收

一次确认落定后，以下五处必须同态：

1. 正式行：一占位只进一正式（bookings 按 hold_id 唯一生效一笔）。
2. 占位态：holds.status 翻 `已确认`。
3. 占用数：slots.booked 只加一次。
4. 互证：`/api/proof/{party_key}` 同源可读，一占一正。
5. 审计：audit_trail 确认痕只有一条；对账 `/api/reconcile` ok。
